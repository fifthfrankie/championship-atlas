## Build (only if Step 0 passes)
- Fetching: one page holds every player with club, so one request per run. Add to `make ingest` through `_Run` in `atlas/cli.py`, with cap (3 per run) and spacing (7 s) as parameters of `_Run`, not a copy. Skip the fetch when the last good FBref snapshot is under 7 days old, enforced in code. Switch: environment variable `ATLAS_FBREF`, on by default locally; in the workflow pass it from repository variable `FBREF_ENABLED`, off unless `true`. No new job or schedule. Snapshots git-ignored unless the terms explicitly permit redistribution. Note that FBref has never been fetched from a GitHub runner.
- Parsing (`atlas/fbref.py`): `html.parser` only; the stats table may sit inside an HTML comment, so feed comment text back through the parser and handle both. Read cells by `data-stat`, never by position, and confirm the names against the saved page. Player and club keys come from ids in `/en/players/<id>/` and `/en/squads/<id>/` links, never names. Empty cell is NULL, never 0. A player missing from the table is "not listed by the provider". Parser test on a fixture (committed real page only if terms permit; otherwise a hand-written test-only fixture).
- Storage: one row per player, per club, per season (a mid-season mover has two rows, never summed silently). Columns: matches, starts, minutes, goals, assists, penalties scored and attempted, yellow and red cards, plus name, nation, position, birth year as supplied; keep `snapshot_id`, our `fetched_at` and the provider's own update time separately. Do not store FBref's per-90 columns: per-90 is calculated once in `atlas/export.py` from counts and minutes, with a plain-English note, shown only above a documented minimum of minutes and otherwise "Too few minutes". xG and other advanced columns are out of scope.
- Identity: clubs in a hand-reviewed `data/fbref_clubs.csv` (FBref squad id, FBref name, our team id; 24 rows); validation rejects the build if any FBref club is unmapped. Players link to existing football-data.org players only when same mapped club, same birth year, same normalised full name, and exactly one candidate on each side; record as a `source_id` row. Everything else stays unlinked, is kept, and is counted on the status page. Where both sources give the same figure (top 10 goals) show each with its source and fetch time; never average or overwrite.
- Pages: club squad table gains the FBref columns for every FBref row at that club, linked or not. Player page shows stats only for linked players. Every figure shows source, fetch date and attribution. With no FBref snapshot, every page still builds with the existing Unavailable state.
- Verification: parser fixture; cap and spacing with a fake sleep; the 7 day skip; re-ingest adds no rows; NULL distinct from 0; same name at a different club or birth year not linked; ambiguous pair stays unlinked; all 24 clubs mapped; per-90 below the minimum shows no number; replay twice identical including FBref; fresh screenshots; raise the Makefile test guards; one read-only QA review.
- Docs on completion: STATUS per-90 row flips, cost-ledger FBref row with verified limit and measured requests, source-matrix FBref row and feature classes.
